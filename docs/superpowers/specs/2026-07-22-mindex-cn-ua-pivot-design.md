# Mindex 转向设计：国内手游买量知识图谱知识库

> 2026-07-22 · 已经用户口头确认（YOLO 模式推进）
> 关联：`docs/设计规范.md`（随本次改版修订）、`HANDOFF.md`

## 0. 重定位

Mindex = **面向国内手游买量团队的知识图谱知识库**。

- 主体是知识库本体：图谱 + 检索 + 带引用问答。研究 Agent 降级为知识获取手段之一，与人工导入并列。
- 服务对象：① 下游创意 Agent（AdMuse 等，经 API/Context Pack/MCP）；② 人类编导/策划（经图谱 + chatbot），前者为主。
- 信息源全面国内化：所有置信度输入必须来自国内平台。Steam、Wikipedia、App Store US 无价值，删除。App Store 评论按业务经验无参考价值，退出默认研究计划。

## 1. 设计规范修订（冲突明示）

现行规范三处与新方向冲突，按新方向修订，保留「克制、编辑式精密感」内核：

| 规范原文 | 修订为 |
|---|---|
| §14 避免「复杂知识图谱作为默认首页」 | 允许**克制的索引式图谱**为首页：细线、几何节点、黑白灰主体、蓝色仅高价值节点；禁粒子/流光/3D |
| §10.5 「AI 洞察不应做成聊天机器人页面」 | 允许**对话式检索**：回答=结论+引用+置信度的诚实结构，非自由闲聊 |
| §11.3 AI 处理中状态（闪烁 star-pulse） | 十字星工作态=**缓慢匀速旋转**（~2.4s/圈，可选极轻微四角伸缩），禁闪烁/呼吸光 |

## 2. 信息架构

- `/` = 全局知识图谱。项目为一级节点，下钻实体（角色/卖点/竞品/人群…，复用 `entities` + `claim_entities`，不动模型层）。
- 图谱下方：问答输入框（纯问答）+ 独立「✦ 新研究」按钮（走现有建项目流程）。
- 点击节点 → 右侧上下文面板：实体关联 claims、引用、置信度、来源。
- 原 Dashboard 运营信息（最近更新/待审/API 调用）移至二级页面「动态」，不删。

## 3. 图谱渲染

- `d3-force`（仅力导向模块）+ 自绘 SVG。不用 cytoscape/three.js（默认长相即规范要避免的神经网络图）。
- 节点：几何形状区分实体类型，等宽字体标签，claim 数决定大小，置信度决定蓝色用量。
- 图谱定位结论（用户委托界定）：**导航与信任展示层好用；查询主通道不好用**。看和逛给图谱，查和问给输入框。
- 数据端点：`GET /app/graph`（全局：项目+核心实体+边）、复用 `GET /app/projects/:id/entities`（下钻）。

## 4. Chatbot（对话式检索）

- `POST /app/chat`：检索（现有 jieba FTS5 + RRF）→ top claims + 证据 → LLM 严格提示（只答库内知识、逐条引用 claim、证据不足明说不知道）→ 流式返回。
- 回答结构：结论 + 引用条目（来源/置信度/点击跳 claim 详情）。多轮历史客户端持有，随请求下发。
- LLM 走现有 provider 体系（生产 DeepSeek）。

## 5. 十字星动画

工作态 `star-pulse`（闪烁）→ 缓慢匀速旋转 ~2.4s/圈。参考主流 AI 产品（Gemini/ChatGPT/Claude）共性：缓旋+轻微形变，无闪烁。

## 6. 连接器收缩

- **物理删除**：`steam.ts`、`wikipedia.ts`、注册表引用、相关测试、`seed-demo`（Steam 录制数据，使命完成）。
- `itunes.ts`：仅保留 CN 元数据（版本/开发商 → official_fact）；删 US 端点与评论抓取。
- 项目 kind 收缩为 `game`（DB CHECK 与 UI 同步）。
- `authority_prior` 国内源重标定：官网 > TapTap 官方页 > 行业媒体 > UGC。

## 8. 信息源路线

- 先出《国内手游买量信息源评估报告》（deep research，逐家给可行性/合规性/接入方式），用户确认后接入。
- 已定原则：**免费官方库优先自动化**（巨量创意灵感库、巨量算数等）；**付费 SaaS（DataEye/App Growing/广大大）无公开 API，走人工导入**；抖音/快手评论复用已付费 TikHub。
